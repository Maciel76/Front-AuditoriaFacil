# 2026-05-19 — Sistema de gamificação e conquistas configuráveis

## Contexto
O portal do colaborador ganhou um sistema completo de gamificação. As conquistas deixaram de ser regras hardcoded no `auditoriaProcessor` e passaram a ser cadastros configuráveis pelo SUPER_ADMIN, com tiers (Comum, Raro, Épico, Lendário, Mítico), XP bônus e progresso dinâmico. O portal foi reformulado para ser mobile-first com bottom navigation.

## Mudanças

### Backend

#### `models/Conquista.js` (novo)
Modelo `Conquista` com `codigo` (único, A-Z0-9_), `nome`, `descricao`, `icone` (emoji), `cor`, `categoria` (`ITENS|AUDITORIAS|CONFORMIDADE|PONTUACAO|NIVEL|ESPECIAL`), `metricaBase` (`totalItensLidos|totalItensConformes|totalAuditorias|taxaConformidadeAcumulada|pontuacao|nivel`), `operador` (`gte`), `recorrente` (bool), `tiers[]` (`{nivel,meta,xpBonus,titulo}`), `ativa`, `ordem`. Pre-save ordena tiers por meta. Exporta `TIERS`, `TIER_INFO`, `METRICAS_SUPORTADAS`, `CATEGORIAS`.

#### `models/Colaborador.js` (atualizado)
Subdocumento `conquistas[]` substituído por `{ codigo, tierAtual, tiersDesbloqueados[], progresso, desbloqueadaEm, ultimaAtualizacao }`. Permite recorrência por tier sem perder histórico.

#### `services/conquistasService.js` (novo)
- `carregarConquistasAtivas()` com cache TTL 30s; `invalidarCacheConquistas()` exposto para mutações.
- `avaliarConquistas(colab)`: percorre conquistas ativas, calcula tier mais alto a partir da métrica base, atualiza `colab.conquistas` in place, soma `xpBonus` em `colab.pontuacao` ao desbloquear novos tiers. Retorna eventos para auditoria/log futuro.
- `resolverConquistasPortal(colab)`: enriquece a lista para o portal (label/cor por tier, próximo tier, `progressoPct`, `totalTiersDesbloqueados/totalTiers`, `desbloqueada`).

#### `services/conquistasSeed.js` (novo)
`semearConquistasSeNecessario()` cria 6 conquistas padrão se a coleção estiver vazia: `ITENS_LIDOS`, `AUDITORIAS`, `CONFORMIDADE`, `PONTUACAO`, `NIVEL`, `ITENS_CONFORMES` — cada uma com 5 tiers.

#### `services/auditoriaProcessor.js` (atualizado)
Removida a lista hardcoded de conquistas e a função `aplicarConquistas`. Agora chama `await avaliarConquistas(colab)` e recalcula nível antes de salvar.

#### `routes/conquistas.routes.js` (novo)
- `GET /meta` — listas auxiliares (tiers, categorias, métricas) para admin/portal autenticados.
- `GET /portal/me` — exposta para o portal (`autenticarColaborador`).
- `GET /` — lista paginada com filtros (admin).
- `POST /`, `PUT /:id`, `DELETE /:id`, `POST /:id/recalcular` — restritos a SUPER_ADMIN, validação Zod, invalidam cache.

#### `server.js` (atualizado)
Registra `app.use("/api/conquistas", conquistasRoutes)` e chama `semearConquistasSeNecessario()` após `connectDB()`.

#### `routes/metricas.routes.js` (atualizado)
Em `/portal/me`, agrega `AuditItem` por `(local, tipo)` para gerar `corredores[]` (top 60 por `totalLidos`) e adiciona `conquistas` resolvidas via `resolverConquistasPortal`.

### Frontend

#### `views/AdminConquistas.vue` (novo)
CRUD completo de conquistas para SUPER_ADMIN. Lista em cards (ícone, código, categoria, badge recorrente/inativa, métrica, tiers em chips coloridos), filtro por categoria, modal de edição com editor de tiers (adicionar/remover, definir meta e XP).

#### `views/ColaboradorPortal.vue` (redesign mobile-first)
Reescrito do zero. Bottom navigation com 4 abas:
- **Início**: card de nível com barra de XP, KPIs de conformidade por tipo (ETIQUETA/PRESENCA/RUPTURA), 4 conquistas em destaque, gráfico de itens por dia.
- **Conquistas**: resumo de tiers desbloqueados, filtros por categoria e status (todas/desbloqueadas/bloqueadas), grid responsivo de cards gameficados (ícone com gradient por tier, barra de progresso até o próximo tier, pílulas de cada tier).
- **Corredores**: lista dos `(local, tipo)` em que o colaborador atuou, com totais e taxa de conformidade.
- **Configurações**: foto do perfil (com cropper), tema (claro/escuro), troca de senha, sair.

`ConquistaCard` é definido localmente via `defineComponent` com render function `h()` (evita parser de template em runtime e mantém o componente no mesmo arquivo). Estilos do card estão em bloco `<style>` não-scoped para que as classes globais sejam aplicadas ao DOM gerado pelo render function.

#### `router.js` (atualizado)
Nova rota `/admin/conquistas` (`meta.roles: ["SUPER_ADMIN"]`).

#### `layouts/AppLayout.vue` (atualizado)
Item de menu "Conquistas" (ícone `trophy`) visível apenas para SUPER_ADMIN; mapa de títulos atualizado.

## Validação
- `node --check` em todos os arquivos backend novos/alterados → OK.
- `npm run build` no frontend → OK (149 módulos, build em 5s).

## Observações
- O cache TTL de 30s em conquistas evita N+1 no processador. Toda mutação no admin invalida o cache.
- O bônus de XP (`xpBonus`) é creditado em `colaborador.pontuacao` no momento do desbloqueio do tier — conquistas recorrentes com múltiplos tiers podem atribuir XP cumulativo.
